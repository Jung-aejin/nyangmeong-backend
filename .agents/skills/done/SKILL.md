# 세션 마무리

1. 이 세션에 `/verify` 보고가 있으면 그 판정과 종료 코드를 쓴다. 없으면 AGENTS.md의 검증 명령을 하나씩 돌리고 종료 코드를 적는다. 명령이 하나라도 0이 아니거나 `/verify` 판정이 `통과`가 아니면 이 세션의 작업은 끝나지 않은 것이다.
2. `git status -sb`와 `git log --since=midnight --oneline`으로 이 세션에서 한 일을 모은다. 기억이 아니라 명령 출력을 근거로 쓴다.
3. `handoff/<이름>.md`(`<이름>`은 브랜치 이름, `/`가 있으면 앞부분)의 "지금 하는 것"을 결과로 바꾼다: 끝남 또는 진행 중, 그리고 한 줄 설명. 1번이 통과이고 마일스톤 작업이 끝났을 때만 `milestones/<이름>.md`의 그 마일스톤 상태를 `끝`으로 바꾼다. 아니면 `진행`으로 둔다.
4. 남은 일은 "다음에 할 것"에 추가한다. 1번에서 실패한 명령이 있으면 맨 위에 적는다. 파일이 60줄을 넘으면 끝난 항목을 지우고, 지운 항목을 보고에 적는다. 핸드오프는 `/start`가 매번 통째로 읽으므로 짧게 쓴다.
5. `cp -R .claude/skills/. .agents/skills/` 다음 `diff -r .claude/skills .agents/skills`를 돌린다. 차이가 없어야 한다.
6. 커밋은 하지 않고 제안만 한다. 1번이 통과이고 마일스톤 작업이 끝났으면 코드·핸드오프·마일스톤 상태를 한 커밋으로 묶는 메시지를 `docs/convention/git.md` 형식으로 제안한다: 제목 `[이니셜] feat: <화면 ID> <화면명>`, 본문에 구현한 기능 ID. 아니면 `[이니셜] docs: 핸드오프 갱신`을 제안한다. `Co-Authored-By:` 같은 AI 도구 줄은 넣지 않는다. 사용자가 "커밋"이라고 답하면 그 메시지로 커밋한다. 푸시와 PR은 하지 않는다.
7. 보고: 첫 줄에 검증 명령별 종료 코드(실패면 실패 줄), 바뀐 절, 화면 확인 결과, 동기화 결과, 확인하지 못한 것. 마지막 줄에 다음 단계를 적는다. 1번이 통과면 "다음 작업은 `/clear` 한 뒤 `/start`로 시작하세요", 아니면 "이 작업은 끝나지 않았습니다. `/clear` 한 뒤 `/start`로 실패 항목부터 이어 가세요"라고 적는다. 지금까지의 대화를 들고 다음 작업을 하면 그만큼 토큰을 계속 쓴다.

핸드오프는 공개 저장소에 커밋된다. 비밀값과 개인 PC 경로를 적지 않는다.
