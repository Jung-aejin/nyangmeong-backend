# 세션 시작

1. `git branch --show-current`로 브랜치를 본다. `develop`·`main`이면 "자기 이니셜 브랜치로 옮긴 뒤 다시 시작하세요"라고 말하고 멈춘다.
2. `<이름>`은 브랜치 이름(자기 이니셜, `/`가 있으면 앞부분)이다. `handoff/<이름>.md`가 없으면 `## 지금 하는 것`, `## 다음에 할 것` 두 절로 만든다.
3. 그 파일 전체를 읽는다. `AGENTS.md`는 세션을 시작할 때 이미 읽혀 있으므로 다시 읽지 않는다. `docs/convention/`은 작업이 가리킬 때 그 파일만 연다.
4. 작업을 하나 고른다. 사람에게 고르라고 묻지 않는다. 고르기와 기획을 한 턴에 끝내야 기획이 이 스킬의 모델로 돈다.
   - 인자 `$ARGUMENTS`에 화면 ID(예: `COM-003` 또는 `SCR-COM-003`, 대소문자 무시)가 있으면 `milestones/<이름>.md`에서 그 화면 ID의 마일스톤을 고른다. 없으면 "이 화면 ID의 마일스톤이 없습니다"라고 말하고 멈춘다. 인자가 비었거나 `$ARGUMENTS`가 글자 그대로 보이면 인자가 없는 것이다.
   - 인자가 없으면 "다음에 할 것"의 맨 위를 고른다.
   - 그것도 비면 `milestones/<이름>.md`에서 상태가 `대기`인 맨 위 마일스톤을 고르고 그 절만 읽는다. "기다리는 것"은 고르는 조건이 아니다. 남의 것을 기다려도 고른다.
   - 마일스톤 파일이 없으면 멈추지 않고 `docs/convention/milestone.md` 절차로 `milestones/<이름>.md`를 만든 뒤, 바로 위 규칙으로 마일스톤을 고른다. 7번 보고 맨 앞에 마일스톤 목록(화면 ID·화면명·상태)과 "대조" 절, 제외한 기능 ID를 보여 준다.
5. "지금 하는 것"에 승인되지 않은 이전 기획이 있으면 지우고, 그 마일스톤 상태를 `대기`로 되돌린다. 그다음 고른 작업 한 줄과 시작 시각을 적고, 마일스톤이면 상태를 `진행`으로 바꾼다.
6. 기획한다. 마일스톤이면 그 화면 ID의 기능 설명(기능명세서 "기능 목록")과 화면설계서의 그 화면 부분을 DMS에서 읽는다. 기획은 화면에 보여 주기 전에 먼저 "지금 하는 것" 아래에 기능 ID별로 한 줄씩 쓴다: 바꿀 파일, 부를 API(남의 것이면 담당 이니셜), 완료 조건. 완료 조건은 `명령:`(AGENTS.md의 검증 명령)과 `화면:`(브라우저에서 확인할 동작)으로 나눈다. 부를 API가 아직 없으면(남의 것이 나오지 않았으면) 그 줄에 "가짜 응답으로 먼저 만들고 나중에 연결"과 가짜를 둘 곳을 적고, 그 API에 기대는 완료 조건은 가짜 응답 기준으로 쓴다. 연결은 "다음에 할 것"에 남긴다. 중간에 끊겨도 `/verify`가 읽을 기획이 남아야 한다.
7. 핸드오프에 쓴 기획을 보여 주고 멈춘다. 보고 끝에 다음을 안내한다: 기획대로 가려면 "승인"이라고 답하고, 고칠 점이 있으면 그 내용을 답한다. 구현은 프로젝트 기본 모델(Sonnet)로 돈다. 다른 마일스톤을 원하면 `/start COM-003`처럼 화면 ID를 붙여 다시 실행한다.
8. 승인 전에는 코드를 쓰지 않는다. 승인되면 기획에 적은 파일만 고쳐 구현하고 검증 명령을 돌린다. 통과하면 "`/verify`로 검증하세요"라고 안내한다. 실패하면 고쳐서 다시 돌리고, 기획 밖 파일을 고쳐야 풀리는 실패면 멈추고 그 파일과 이유를 보고한 뒤 "기획을 고칠지 정해 주세요"라고 안내한다.

핸드오프는 공개 저장소에 커밋된다. 비밀값과 개인 PC 경로를 적지 않는다.
