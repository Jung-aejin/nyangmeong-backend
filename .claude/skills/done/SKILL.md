# 세션 마무리

`<이름>`은 브랜치 이름이다(`/`가 있으면 앞부분). 기억이 아니라 명령 출력을 근거로 쓴다.

1. 검증: 이 세션의 마지막 검증 보고(`/build` 또는 `/verify`)의 판정을 쓴다. 없으면 AGENTS.md의 검증 명령을 돌린다. 명령이 0이 아니거나 판정이 `실패`면 작업은 끝나지 않았다. `확인 못 함 있음`이면 5번 기준으로 본다.
2. 사람 확인: 사람이 확인했다고 답한 적이 없으면 확인 목록을 보여 주고 멈춘다. 환경(`.env.local`·`application.properties`, 남의 API)이 없어 확인할 수 없어 보여도 대신 판단하지 않고 묻는다. README를 보라고만 하지 않는다.
   - 검증 보고의 "사람 확인"을 그대로 옮긴다. 없거나 빠진 기능 ID는 기획과 코드로 같은 형식으로 만든다.
   - 띄울 명령(어느 저장소에서), 브라우저에 붙여 넣을 전체 URL, 할 동작 → 기대 결과가 있어야 한다.
   - 끝에 "확인했으면 `확인`, 문제가 있으면 그 내용을 답해 주세요". 답을 받으면 3번부터 이어 간다.
3. `git status -sb`, `git log --since=midnight --oneline`으로 한 일을 모은다.
4. 검증 루프 잠금을 푼다(`sh scripts/verify-loop.sh clear`). 그다음 `handoff/<이름>.md`를 고친다.
   - "지금 하는 것": 끝남 또는 진행 중, 한 줄 설명.
   - "다음에 할 것": 남은 일. 실패한 명령이나 사람이 답한 문제는 맨 위.
   - 60줄을 넘으면 끝난 항목을 지우고 보고에 적는다.
5. 마일스톤 `끝` 판정은 여기서만 한다. 아래를 모두 만족하면 `milestones/<이름>.md`의 그 마일스톤을 `끝`으로, 아니면 `진행`으로 둔다. 판정과 근거(못 맞춘 항목)를 보고에 적는다.
   - 검증 명령이 모두 0이고 판정이 `실패`가 아니다.
   - 마일스톤의 기능 ID가 모두 셋 중 하나다: 검증 보고에서 통과, `연결 남음`, 기획에서 다른 마일스톤으로 넘김.
   - 검증 보고의 "확인 못 함(내 것)"이 없다.
   - 사람이 `확인`이라고 답했다(2번).
   - `끝`이면 그 마일스톤 절에 `- 연결 남음: <기능 ID> (<기다리는 것>, <담당>)`을 남기고, 같은 항목을 핸드오프 "다음에 할 것"에 올린다.
6. `cp -R .claude/skills/. .agents/skills/` 후 `diff -r .claude/skills .agents/skills`. 차이가 없어야 한다.
7. 커밋 메시지를 제안한다(`docs/convention/git.md` 형식). 종류는 들어가는 변경으로 정한다.
   - 코드가 있으면 코드·핸드오프·마일스톤을 한 커밋으로. 제목 `[이니셜] feat: <화면 ID> <이번에 만든 것>`(버그 수정만이면 `fix`). 화면명이 아니라 실제로 만든 것을 쓴다.
   - 본문: 진행 중이면 첫 줄에 "진행 중"과 남은 것. 기능 ID별 한 줄. 남에게 영향이 있으면 "영향:" 줄(새 환경변수·설정 변경, 추가한 라이브러리, 공유 파일, 남과 맞출 결정).
   - `handoff/`·`milestones/`만 바뀌었으면 `[이니셜] docs: 핸드오프 갱신`.
   - `.claude/skills/`·`.agents/skills/` 변경이 섞여 있으면 "공용 하네스 변경이 섞여 있습니다. PR로 따로 올리세요"라고 알리고 커밋에서 뺀다. 6번 동기화로 생긴 변경도 같다.
   - `Co-Authored-By:` 같은 AI 도구 줄은 넣지 않는다. 사람이 `커밋`이라고 답하면 커밋한다.
   - 커밋한 뒤 푸시를 제안한다: 올릴 커밋 목록(`git log origin/<이름>..HEAD --oneline`)을 보여 주고 "푸시하려면 `푸시`라고 답해 주세요". 답하면 `git push origin <이름>`만 한다. `develop`·`main`에는 푸시하지 않는다.
   - 푸시한 뒤 PR: `gh pr list --head <이름> --state open`으로 열린 PR이 있으면 "이 커밋은 열린 PR #N에 들어갑니다"라고만 알린다. 없고 이번 마일스톤이 `끝`이면 "PR을 만들려면 `PR`이라고 답해 주세요"라고 묻는다(`진행`이면 묻지 않는다).
   - `PR`이라고 답하면: `git fetch` 후 `origin/develop`을 merge한다(rebase 하지 않는다. 충돌이 나면 멈추고 알린다) → 검증 명령을 다시 돌린다 → 푸시 → `gh pr create --base develop --head <이름>`. 제목은 커밋 형식, 본문은 화면 ID·기능 ID, 무엇을 왜 바꿨는지, 어떻게 확인했는지(검증 판정, 사람 확인), "영향:". AI 도구 문구는 넣지 않는다. `gh`가 없으면 `https://github.com/<저장소>/compare/develop...<이름>` 주소와 본문을 보여 준다.
   - 병합은 하지 않는다. 사람이 GitHub에서 한다.
8. 보고: 검증 명령별 종료 코드, 사람 확인 결과, 바뀐 절, 동기화 결과, 확인 못 한 것. 마지막 줄:
   - 끝났으면 "다음 작업은 `/clear` 한 뒤 `/start`로 시작하세요"
   - 아니면 "이 작업은 끝나지 않았습니다. `/clear` 한 뒤 `/start`로 이어 가세요"

핸드오프는 공개 저장소에 커밋된다. 비밀값과 개인 PC 경로를 적지 않는다.
